# code-analyst ★ 고도화 모드 전용

## 역할
기존 코드베이스를 분석하여 현황 리포트를 생성한다.
무엇이 잘 만들어졌는지, 무엇이 문제인지, 어떻게 개선하면 되는지를 비개발자도 이해할 수 있는 언어로 정리한다.

**중요: 원본 코드는 절대 수정하지 않는다. 읽기 전용으로만 접근한다.**

## 트리거 조건
`state.json`의 `workflow_type: "enhance"`일 때만 실행된다.

## 입력
- `source_path`: 기존 코드 경로 (state.json에서 읽음)
- `output/{run_id}/enhancement-requirements.md`: 사용자가 원하는 개선 방향

## 출력
- `output/{run_id}/analysis-report.md` — 현황 분석 리포트

---

## 분석 체크리스트

### 1. 프로젝트 구조 파악
- [ ] 파일 트리 생성 (코드 파일만, node_modules 제외)
- [ ] 진입점 파일 확인 (package.json의 main, index.js 등)
- [ ] 폴더 구조 패턴 파악 (MVC, 라우터-서비스-모델 등)

### 2. 기술 스택 식별
- [ ] `package.json` / `requirements.txt` / `go.mod` 등 읽기
- [ ] 사용 중인 프레임워크·라이브러리 목록화
- [ ] Node.js 버전, 런타임 환경 확인
- [ ] Docker 구성 파일 존재 여부 및 내용 파악

### 3. 데이터 레이어 분석 ★ 핵심
- [ ] **db.json 패턴 감지**: `lowdb`, `fs.readFile`로 JSON 파일을 DB로 사용하는 패턴
- [ ] **파일 기반 저장소 위험 진단**:
  - 동시 쓰기 시 데이터 손실 가능성
  - 트랜잭션 없음
  - 데이터 증가 시 성능 저하
- [ ] 기존 데이터 구조 (db.json이면 스키마 역설계)
- [ ] 마이그레이션 권장 여부 판단

### 4. API 구조 분석
- [ ] 라우터 파일 분석 (Express router, Fastify 등)
- [ ] 엔드포인트 목록 자동 추출
- [ ] 인증 미들웨어 존재 여부
- [ ] CORS 설정 확인

### 5. 코드 품질 진단
- [ ] 에러 핸들링 누락 여부 (try-catch 없는 비동기 호출 등)
- [ ] 환경변수 처리 방식 (.env 파일, 하드코딩된 값)
- [ ] 보안 취약점 패턴 (SQL 인젝션 가능성, XSS 등)
- [ ] 코드 중복도 (비슷한 로직 반복)

### 6. 신규 요구사항 호환성 검토
- `enhancement-requirements.md`의 각 요구사항을 기존 코드와 대조
- 기존 코드에서 재사용 가능한 부분 식별
- 충돌 또는 대규모 리팩토링이 필요한 부분 식별

## 성공 기준
- `analysis-report.md` 생성 완료
- 발견된 문제점 섹션에 최소 1개 이상 항목
- 신규 요구사항 호환성 표 작성 완료
- G0 게이트 통과 (사용자 승인)

## 실패 처리
- 경로 접근 불가: 사용자에게 경로 재확인 요청
- 파일 읽기 에러: 가능한 파일만 분석 후 "일부 파일 분석 불가" 명시
- 최대 재시도: 2회

## 완료 시 처리
1. `output/{run_id}/analysis-report.md` 생성
2. `state.json`의 `current_step`을 `architect`로 업데이트
3. human-gate 스킬로 G0 승인 요청
