# requirements-elicitor 스킬

## 목적
요구사항 인터뷰를 수행하고, 수집된 정보를 구조화된 requirements.md로 변환한다.

---

## 복잡도 분석 기준

사용자의 초기 요청을 분석하여 인터뷰 깊이를 결정한다.

| 복잡도 | 기준 | 질문 수 |
|--------|------|---------|
| 낮음 | 기능 1~2개, 사용자 유형 명확, 제약 없음 | 1~2개 |
| 중간 | 기능 3~5개, 일부 모호, 역할 있음 | 3~4개 |
| 높음 | 기능 6개 이상, 워크플로우, 다중 사용자, 외부 연동 | 5~7개 |

---

## 인터뷰 질문 풀

요청 내용과 복잡도에 맞는 질문을 아래에서 선별. 한 번에 최대 2개만 질문.

### 목적 관련
- 이 앱이 해결하려는 핵심 문제가 무엇인가요?
- 현재는 어떻게 처리하고 있나요? (수동, 엑셀, 다른 시스템 등)
- 이 앱이 성공했다는 걸 어떻게 알 수 있을까요?

### 사용자 관련
- 이 앱을 주로 누가 사용하나요?
- 사용자에게 다른 역할(권한)이 필요한가요? (예: 관리자, 일반 사용자, 게스트)
- 사용자가 얼마나 많을 것으로 예상하나요?

### 기능 관련
- 가장 중요한 기능 3가지만 꼽는다면?
- 없으면 안 되는 기능 vs 있으면 좋은 기능을 구분해주실 수 있나요?
- [언급된 기능]에서 [구체적인 시나리오]도 처리해야 하나요?

### 비기능 관련
- 모바일에서도 사용해야 하나요?
- 여러 사람이 동시에 접속할 때 느려지면 안 되는 상황이 있나요?
- 개인정보나 민감한 데이터가 포함되나요?

### 제약 관련
- 기존에 사용 중인 시스템과 연결해야 하나요?
- 특정 인프라 또는 회사 정책 제약이 있나요?
- 언제까지 만들어야 하는 일정이 있나요?

## requirements.md 작성 지침

### 필수 섹션 5개 체크리스트
- [ ] **목적**: 앱이 해결하는 문제와 달성 목표 (1~3문장)
- [ ] **사용자 및 페르소나**: 누가 사용하는가, 역할별 특성
- [ ] **핵심 기능**: 주요 기능 목록 (각 기능을 사용자 관점 1~2문장)
- [ ] **비기능 요구사항**: 성능, 반응형, 보안, 접근성 등
- [ ] **제약사항**: 기술, 일정, 인프라, 연동 시스템 등

### 작성 원칙
- 사용자의 원래 언어로 작성 (기술 용어 최소화)
- 개발자가 읽어도, 비개발자가 읽어도 이해 가능한 수준
- 기능은 "사용자가 ~를 할 수 있다" 형식으로
- 불확실한 부분은 "[미결: ...]"로 표시하고 추후 확인

## 완료 판단 규칙
5개 필수 섹션 모두 비어있지 않으면 완료. 
자동 체크:
```python
required_sections = ["## 1. 목적", "## 2. 사용자", "## 3. 핵심 기능", "## 4. 비기능", "## 5. 제약"]
all_filled = all(section in content and len(content.split(section)[1].strip().split("\n##")[0].strip()) > 10 
                 for section in required_sections)
```
